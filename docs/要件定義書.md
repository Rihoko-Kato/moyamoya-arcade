## 1. 研究全体の中での位置づけ

| 項目 | 内容 |
|---|---|
| 役割 | 研究全体の③。**日常で気軽に触れられる入口** |
| 使い方 | 暇つぶしのゲームくらいの気持ちで、空いた時間に気軽に遊ぶ |
| 期待できる効果 | ただ時間をつぶすだけではなく、ちょっと前向きになるきっかけになること。**クスッと笑って、失敗を楽しい方に昇華**してほしい |

## 2. 大きな目標・ゴール（研究全体と共通）

- 一つの失敗をきっかけに、過去の失敗まで掘り返して、自分の嫌いなところが次々に出てくる「負のループ」を止めたい。人格を否定し続けると、「ダメな自分」を言い訳にして改善できなくなってしまうから。
- 失敗しても事実は残るので、反省も改善も必要。そのときに自己批判に走るのではなく、事実は事実として受け止め、完璧じゃなくても、上手にできなくても、頑張った自分をちゃんと認められるようになってほしい。
- 自分を好きにさせたいのではない。完璧ではない自分をそのまま受け入れて、大事にしてほしい。自分で自分を苦しめる必要はないのだと思えるように。

### 期待する効果（全体）

視点を変えて落ち着いて考える方法を、ゲームの中で見せる。普段からそう考えるための**お手本（デモンストレーション）**になること。

アーケードでは、次の考え方を「お手本」の候補とする。

| 記号 | 考え方 |
|---|---|
| M1 | 起きた**事実**と、自分を責める**解釈**は別のもの |
| M2 | 事実は思い込みと違ったかもしれない |
| M3 | 自分だけじゃない |
| M4 | 結果が思いどおりでなくても、やったこと（過程）は残る |
| M5 | 完璧じゃないところも、その人らしさ（価値になることもある） |
| M6 | 大きな世界から見れば、ひとつの出来事にすぎない |
| M7 | ひと晩おけば、たいていのことは落ち着いて見られる |

## 3. 対象と遊ぶ場面

- **対象**：失敗を引きずりがちで、自分が嫌いだと思ってしまう、自己批判の強い人。
- **遊ぶ場面**：落ち込んでいるときに限らない。いつ出会っても遊べる。苦しいときに思い出せば、冷静になるきっかけになる。
- **前提**：ふだん（落ち込んでいないとき）に遊んで楽しいこと。楽しくなければ、苦しいときに思い出してもらえない。

## 4. 設計原則

| 番号 | 原則 | 内容 |
|---|---|---|
| P1 | **言わずに、遊ばせる** | メッセージは言葉で伝えず、ルールそのものに埋め込む。言葉で伝えると押し付けになるため（制作記録：第1版で「全て押し付けがましい」と感じて作り直した） |
| P2 | **ゲームとして楽しいことが前提** | 遊ぶ理由は「楽しいから」。テーマのために楽しさを削らない |
| P3 | **感情を否定しない** | 「落ち込む必要はない」「気にしなくて大丈夫」のように、気持ちそのものを否定・断定する言葉は使わない。手放すのは「自分を責める解釈」であって、気持ちではない |
| P4 | **評価で褒めない** | 「えらい」「すごい」など、点数以外で人を評価する言葉は使わない（自己肯定の押し付けを避ける） |
| P5 | **失敗を笑いに変える** | ミスや失敗の場面に、クスッと笑える仕掛けを入れる。失敗が「痛いもの」ではなく「ちょっと面白いもの」になるように |
| P6 | **気軽さ** | 説明なしで始められる。1プレイは1〜3分。いつやめてもいい |
| P7 | **プライバシー** | プレイヤーが書いた文章は保存も送信もしない。サイトに送るのは数値・回数・種類だけ |

## 5. 共通の要件

### 5.1 遊び方

- 1プレイの長さ：1〜3分を目安。
- 繰り返し遊べる仕組みを、各ゲームに最低1つ入れる（例：だんだん難しくなる、ランダムな変化、自己ベスト）。
- 操作：スマホのタップ・スワイプと、パソコンのキーボード・マウスの両方で遊べる。

### 5.2 画面

- サイトに埋め込んだとき（横長 16:10）と、スマホ単体（縦長）の両方で崩れない。
- 遊び方の説明は、始める前の画面に3〜5行まで。

### 5.3 結果画面

- 出すもの：スコア、自己ベスト（更新したら NEW BEST）、プレイの数値（2〜3個）、**ひとこと**。
- ひとことはキャラのセリフ程度。プレイの様子にだけ触れる（例：「✂ さばき、キレてた」）。研究のメッセージは言わない（P1）。

### 5.4 言葉の決まり

| 使わない | 理由 |
|---|---|
| 「えらい」「すごい」「最高」など人の評価 | P4 |
| 「落ち込む必要はない」「気にしなくて大丈夫」「どうでもいい」 | P3。気持ちの否定・逃げ（「まーいっか」で終わらせる）になる |
| 「あなたは〇〇だ」という決めつけ | 自己受容の押し付けになる |

※ モヤモヤ相談所（6.6）の「適当お告げボット」の「大丈夫」は、キャラの適当さとして笑いにする前提で例外とする（[Q6](#10-未決事項)）。

### 5.5 技術

- HTML / CSS / JavaScript。1ゲーム1ファイル。
- 生成AI（API）は組み込まない。
- 公開：GitHub Pages。記録：Google Apps Script ＋スプレッドシート（`postMessage` で summary と detail を送る）。

## 6. ゲームごとの要件

各ゲームについて「何のお手本か」「ルールへの埋め込み方」「笑いの要素」「今の版とのずれ（直す候補）」を整理する。
「今の版」は 2026-10-08 時点のアーケード版を指す。

### 6.1 事実と感情の仕分け（ギャルと仕分け）

| 項目 | 内容 |
|---|---|
| お手本 | M1（事実と解釈を分ける）、M2 |
| 一新の方向（決定） | **ギャルが隣にいてくれる**。仕分けるたびに一言くれて、間違えたら突っ込んでくれる。研究資料の「頭の中でギャルを飼う」（7/24 p38）、「ギャルマインドの憑依」（7/15 p20）を形にする |
| ギャルの役割 | 事実と思い込みを分ける考え方の**お手本（デモンストレーション）**。説明やメッセージではなく、隣の友だちのリアクションとして聞かせる（P1 と両立する）。ゴールは、プレイヤーが自分の中にも「ツッコんでくれるギャル」を持てるようになること |
| ルールへの埋め込み | 落ちてくるカードを左右に仕分ける（左：気持ち・手放す／右：事実・受け止める）。事実と解釈が混ざったカードは ✂ で切ると、事実は右、解釈は左へ飛ぶ。スコア・コンボ・ハート・だんだん速くなる仕組みは今の版を引き継ぐ |
| 外したときの扱い（決定） | テストのように感じさせない（[Q4](#10-未決事項)）。「COMBO BREAK」の文字と赤い揺れはやめ、カードは「ぽよん」と戻る。**ギャルが笑いながら突っ込む**（例：「待って、それ事実！カメラ映るやつ！笑」）。コンボは静かにリセット |
| 笑いの要素（決定） | ①ギャルのツッコミとリアクション。②大げさすぎる思い込みのカード（例：「店長に声をかけられた。／きっと世界が終わる」→ ギャル「世界は終わんないって笑」）。③手放したカードは丸められてゴミ箱にシュート。④たまにレアな「超事実」カード（例：「今日も地球は回っていた」→「それはガチ」） |
| 結果画面 | スコア・自己ベスト・数値と、ギャルのひとこと（5.3） |

#### ギャルのセリフの決まり

| 決まり | OK の例 | NG の例 |
|---|---|---|
| 人を評価しない（P4） | 「それな」「えぐ」「ノってきたじゃん」 | 「えらい」「すごい」「天才」 |
| ツッコむのは**解釈**で、**気持ち**ではない（P3） | 「それ妄想入ってない？」「考えすぎ〜」「その解釈、重すぎ」 | 「落ち込むな」「気にしなくていいよ」 |
| 外したときは笑いながら、責めない | 「待って、それ事実！笑」「いやそれ想像じゃん笑」 | 「違う」「ミス」「ちゃんと見て」 |
| 正解を説明しない（P1） | 「カメラ映るやつ〜」のように一言でヒント | 「事実とは〜のことです」のような説明 |
| 短く | 1回15文字前後まで | 2文以上の長いセリフ |

#### セリフの場面（例）

| 場面 | 例 |
|---|---|
| 事実を受け止めた | 「それな、ただの事実〜」「事実確認おけ👌」 |
| 気持ちを手放した | 「それ妄想入ってない？ぽいっ」「考えすぎ〜バイバイ👋」 |
| ✂ で切った | 「くっついてたの分けたのえぐ」「事実と気持ち、別居させといた〜」 |
| 事実を捨てそうになった | 「待って、それ事実！カメラ映るやつ！」 |
| 気持ちを受け止めそうになった | 「いやそれ想像じゃん笑」 |
| 混ざったカードをそのまま仕分けた | 「それ2個混ざってない？✂いこ」 |
| 大げさなカード | 「世界は終わんないって笑」 |
| コンボ中 | 「ノってきたじゃん」「連続えぐ」 |
| カードが下まで落ちた | 「あ、見送った〜 次次」 |
| 超事実カード | 「地球回ってるのはガチ」 |

### 6.2 粘土フィギュア工房（旧：粘土うさぎ屋さん）

| 項目 | 内容 |
|---|---|
| お手本 | M5（完璧じゃないところも、その人らしさ）、M4 |
| 設定（決定） | **好きなキャラ（うさぎ）のフィギュアを、趣味で作って棚に飾る**。お客さん・注文など「相手」は出さない（[Q5](#10-未決事項)） |
| ルールへの埋め込み（決定） | 60秒で好きに作り、完成したら棚に飾る。**まだ棚にない形なら「新作！」ボーナス**、同じ形は少しだけ得点。形は4パーツ × 3段階（粘土のまま／整った形／個性的）の81種類で、コレクション図鑑になる。正解の形はなく、いろんな形を作るほど得をする |
| 笑いの要素（決定） | 形ごとに名前がつく（例：耳はまだ粘土っぽい、ずんぐりしたうさぎ）。「全部粘土のまま」は「原型」、「全部個性的」は「超大作」など、ヘンな形ほど面白い名前 |
| 今の版からの変更 | 「注文どおりに作って売る」をやめる。「相手の期待に合わせる」体験は M5 と逆向きになるため |

### 6.3 自己嫌悪ディフェンス

| 項目 | 内容 |
|---|---|
| お手本 | M1（責める解釈は手放し、事実は残す）、M7 |
| ルールへの埋め込み（今の版） | 夜を重ねるサバイバル。むらさき（自己嫌悪）はタップで吹き飛ばし、グレー（事実）はさわらずに通すと得点 |
| 笑いの要素（今の版） | 吹き飛ばしたときのおまじない（「まあいっか！」「おふとんの勝ち」） |
| 「吹き飛ばす」の扱い（決定） | 吹き飛ばすのはそのままでよい。気持ちを否定するのではなく、**寝る前に深く考えすぎない**ための行動であるため |
| 吹き飛ばした先（決定） | **吹き飛ばした考えごとが「夢の材料」になる**。①吹き飛ばした考えごとは、柵を飛び越えるひつじに変わる（ひつじを数えて眠る）。②朝の結果画面に「今夜見た夢」が出る。吹き飛ばした考えごとの断片をつなぎ合わせたヘンな夢（例：「店長が、プリンの上で、声を震わせながら空を飛んでいた夢」）。寝る前のぐるぐるが、朝には笑える夢になっている |
| 笑いの要素（決定） | 上の「今夜見た夢」。夜が深まると考えごとがだんだん変になる（「冷蔵庫のプリン食べたっけ」）。ボスの倒れ方がまぬけ |

### 6.5 FACTラン

| 項目 | 内容 |
|---|---|
| お手本 | M4（結果を越えられなくても、走った分は残る） |
| ルールへの埋め込み（今の版） | 各ステージの最後に越えられない壁（「理想」「完璧」など）。ぶつかるとステージクリアで、走った距離はスコアに残る。ゲームオーバーは壁ではなく道中の小石やモヤ雲で起きる |
| 笑いの要素（今の版） | ほぼない |
| 笑いの要素（決定） | ①壁にぶつかると、主人公がせんべいのようにぺしゃんこになってから「ぽよん」と戻る。②壁の言葉にまぬけなもの（「月曜日」「おふとん」「なんかでかい」など）を増やす。③道に寝転がる猫など、思わず笑う障害物を足す |
| ずれ・直す候補 | 特になし。ハートが減る＝失敗の罰が強すぎないかは、プレイテストで確認 |

## 7. 記録とランキング

### 7.1 論点

アーケードの「みんなのランキング」と、「比べて決まる評価に振り回されない」という目標がぶつからないか。
一方で、あくまでゲームとして楽しめることが前提（P2）なので、記録を伸ばす楽しさは残したい。

### 7.2 候補

| 案 | 内容 | 楽しさ | 目標との整合 |
|---|---|---|---|
| A. みんなのランキング（今の版） | 1人1行の上位10人ランキング | ◎ 競う楽しさ | △ 他人との比較になる |
| B. みんなで合計（協力型） | 「今日みんなで手放した考えごと 1,234個」のように全員の合計を出す | ○ みんなで積み上げる楽しさ | ◎ 比較にならず、M3「自分だけじゃない」を見せられる |
| C. 自己ベストだけ | 他の人の記録は出さない | △ 一人で伸ばす楽しさ | ◎ |
| D. B ＋ 自己ベスト | 個人は自己ベストを伸ばし、サイトには全員の合計を出す | ○ | ◎ |

**決定：D**。ゲームとしての「記録を伸ばす」楽しさは自己ベストで残し、みんなの記録は「比べる」から「一緒に積み上げる（自分だけじゃない）」に変える。
ランキング（A）を残す場合は、検証で「ランキングをどう感じたか」を必ず聞く。

## 8. 検証の方法

- ゼミでのプレイテスト。1人あたり2〜3本を遊んでもらう。
- 遊んだあとに聞くこと（案）：
  1. 楽しかったか／もう一回遊びたいか
  2. このゲームは何を伝えたかったと思うか（伝わり方の確認。P1 が機能しているか）
  3. 押し付けがましさを感じた場面はあったか
  4. クスッと笑えた場面はあったか（P5）
  5. 記録・ランキングをどう感じたか（7章）
- サイトの記録（スプレッドシート）で、プレイ回数と繰り返し遊んだ人の数を見る。新しい版の記録は 2026-10-08 以降。

## 9. スコープ外

- 生成AIによる応答。
- 書いた文章の保存・分析。
- 物語のあるロールプレイ（研究全体の別の作品で扱う）。
